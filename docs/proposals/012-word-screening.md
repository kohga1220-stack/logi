# 提案 012: 追加語の事前スクリーニング（LLM の助言）

状態: **決定済み（2026-10-17）**。M1ko が「すべて A」と返事をしたので、Q1〜Q3 はすべて A（試験運用・助言だけ・無料枠のモデルから）。ツール `tools/screen_words.py` は書いた。第4弾 50 語での測定は、鍵（環境変数）が要るため、鍵を用意してもらってから行う。採用は、その数字を見て M1ko が決める。

## 1. 何が足りないか

Antigravity が追加語を出す PR には、語ごとの事前確認の表が付きます（`docs/WORKFLOW.md` §2 の5）。しかし、この表は、**英語の見出し語が日本語の意味に合っているか**を、確かめられていません。実績です。

| バッチ | 語数 | 見直しで直した・外した語（または修正推奨）| 割合 |
|---|---|---|---|
| 第2弾（PR #37）| 26 | 7 | 約 27% |
| 第4弾（PR #54）| 50 | 6（Claude の確認での修正推奨。M1ko の確認前）| 12% |

第4弾の修正推奨 6 語は、どれも、事前確認の表では「問題なし」でした。

| 語 | 問題 |
|---|---|
| `jikia` 億 | billion は 10 の 9 乗。億は 10 の 8 乗で、**事実の誤り** |
| `pawusa` ボールペン | 既存の `pena`（ペン）と意味が重なる |
| `ejisa` 以外 | except の意味で、exception は違う。前置詞に近く機能語 |
| `simapa` 気の毒 | pity に近く、sympathy は違う |
| `pupito` 飼う | breed は繁殖の意味。rear が近い |
| `pakako` 空く | vacate は他動詞。empty が近い |

確認の手間は、語数が増える（第4弾から 50 語）ほど大きくなります。そこで、語を PR に出す前に、**LLM に「英語の見出し語が日本語に合っているか」を助言させる**ことを検討します。

## 2. 手がかり（すでにある決まり）

- 辞書は公開リポジトリの内容で、語と意味だけです。個人情報や認証情報は含みません。
- 既存の語の削除・書き換えは、M1ko が方針を決めてからです（§2 の3）。LLM に、辞書を変えさせません。
- 追加語の最終的な確認は、M1ko です（`word_review.csv` の `ok` / `fix`）。
- Claude も、PR ごとに追加語を確認し、note に書いています（M1ko の依頼、2026-10-17）。
- LLM を呼び出す仕組みは、別のプロジェクト（NoUs・litwiki）で、モデル名の接頭辞で呼び先を選ぶ方式が検討されています（別セッションの記録。このリポジトリでは未確認）。

## 3. 提案

### Q1. 試験運用をするか

LLM の助言が、人の確認とどれだけ合うかは、まだ分かりません。まず、第4弾の 50 語で試します。

| 案 | 内容 |
|---|---|
| **A（おすすめ）** | **試験運用**。手元で LLM に第4弾の 50 語を助言させ、Claude が手で見つけた 6 語（修正推奨）と 13 語（任意）と、どれだけ合うかを測る。結果（見つけた数・誤って指摘した数）を、PR で報告する。採用するかは、その数字を見て、M1ko が決める |
| B | 試験なしで、すぐ導入する |
| C | 導入しない（Claude の手での確認を続ける）|

おすすめは A です。理由は、無料モデルの日本語の品質が未確認で、数字なしに導入すると、見落としや誤った指摘が増えるおそれがあるからです。

### Q2. 導入する場合の置き場所と出力

| 案 | 内容 |
|---|---|
| **A（おすすめ）** | **助言だけ**。ツール（`tools/screen_words.py`）が、追加リストの各語に「合う・一部ずれる・ずれる」と、代案を出す。結果は、PR 本文の表の下書きにするだけで、**合否の判定や、辞書の変更はしない**。実行は手元（Antigravity か Claude）。鍵は環境変数で渡し、リポジトリには置かない |
| B | CI（`.github/`）で自動実行し、ずれる語があると PR を止める |
| C | 助言を、確認表（`word_review.csv`）の note に自動で書き込む |

おすすめは A です。理由は、LLM の判断が間違うことがあり、判定を LLM に任せないほうが安全だからです。B は、CI の変更（M1ko のマージが必要）と、鍵の管理が増えます。C は、人の note と混ざります。

### Q3. 助言に使うモデル

| 案 | 内容 |
|---|---|
| **A（おすすめ）** | 無料枠のあるモデルから始める（別のプロジェクトで検討している接頭辞方式に合わせる）。Q1 の試験で、合わなければ別のモデルに変える |
| B | 有料のモデルを使う |
| C | モデルは、実装のときに Claude が決める |

おすすめは A です。送るのは、辞書の語・日本語の意味・英語の見出し語だけです（公開情報）。無料モデルには入力が学習に使われるものがあるため、辞書以外（個人情報・認証情報・非公開の内容）は、送りません。
