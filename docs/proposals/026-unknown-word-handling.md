## 2. 何を解くのか（三つに分けられる）

「辞書にない語をその場で訳す」には、性質の違う三つの仕事が混ざっている。

| # | 仕事 | 例 | LLM は要るか |
|---|---|---|---|
| T1 | 英語の未登録語に、**仮の Logi の形**をつける | `pigeon` → 仮の `pikona` | 要らない。`coin_words.py` の音訳を JavaScript に写せば、ブラウザの中で、無料・オフラインで一瞬でできる |
| T2 | 意味の近い**既存の語**を探す（言い換え案） | 「泣きじゃくる」→ 泣く + とても | 小さい埋め込みモデル（数十 MB）で候補を出せる。文を作るには LLM が要る |
| T3 | 日本語の未登録語に、新しい Logi の語をつける | 「鳩」→ `pikona` | 要る（日本語の音は、音訳ルールの入力にならない）。意味の特定が要る |

T1 は日本語の語には使えない。音訳ルールは英語のつづりが元だからである。

## 3. 選んでほしい点

### Q1. 仮の語の置き場

| 案 | 内容 |
|---|---|
| **A（おすすめ）** | 審査待ちの置き場（`dictionary/pending_words.csv`）に貯める。列: 入力の語・品詞・Logi の形・出どころ（方法、日付）・状態（`pending` / `adopted` / `rejected`）。M1ko または Claude が承認した語だけ `final.csv` に移す。`final.csv`・`lexicon.js` には直接書かない |
| B | `final.csv` に直接書く（仮の印つき）|
| C | 記録しない（毎回その場で作る）|

おすすめは A。理由は、`final.csv` の「同音異義語ゼロ・重複確認」の保証を壊さないため。B は、ANTI の `overlap_check.py` の確認を通っていない語が辞書に混ざる。C は、同じ語が日によって別の形になる（T1 は決まったルールなので同じ形になるが、T2・T3 は揺れる）。

### Q2. 造語の方針

| 案 | 内容 |
|---|---|
| **A（おすすめ）** | まず既存の語の組み合わせ（`grammar.md` §10.2。修飾語 + 被修飾語）か、T2 の既存語への言い換えで言えないかを探す。無理なときだけ、新しい語（T1・T3）を仮の語として作る |
| B | 常に新しい語を作る |

おすすめは A。理由は、Logi は最小主義（`CLAUDE.md`・設計原則）で、辞書は ANTI の重複確認が通った語だけを増やしているため。新しい語の乱造は、辞書の重複（ANTI の癖 A）を、機械で増やすことになる。

### Q3. 提供の形

| 案 | 内容 |
|---|---|
| **A（おすすめ）** | まず手元の道具（CLI。`tools/` に置く）。サイトは、承認後の辞書だけで更新する。サイトの入力が外に送られない約束（`web/README.md`）は守る |
| B | サイトから、無料の API をその場で呼ぶ |
| C | サイトで、ブラウザの中で動く小さいモデルを使う |

B は、鍵をページに埋め込めない（盗まれる）ので、使う人が自分の鍵を入れる形にするしかなく、入力が外に出る。C は、初回に数百 MB 以上のダウンロードになる（未確認。モデルによる）ので、段階2以降の選択肢にする。

## 5. 別セッションの依頼文から取り入れたもの・取り入れなかったもの

| 案 | 判断 | 理由 |
|---|---|---|
| ①意味の特定 → ②辞書を引く → ③候補 → ④機械の検査 → ⑤逆翻訳 → ⑥記録 → ⑦再利用 | 取り入れる（段階1〜3）| ④を LLM の判定より先に置くのは、`validate.py` が機械で検査できるので妥当。⑤の逆翻訳は、既存の翻訳機で Logi → 日本語・英語に戻せるので、実装できる |
| 逆翻訳、自作ベンチ（例文183文と、伏せた既存語）で測る | 取り入れる | 段階3 の前に、「伏せた既存語を言い換え案が当てられるか」を測る。測るまでは精度を主張しない |
| トーナメント式の合成、反復的な自己蒸留 | 見送り | 複数の LLM を回す仕組みで、辞書約 3,200 語・無料枠では、費用に見合うかが未確認。段階3 の結果を見てから |
| PLaMo 3 Translate を使う | **未確認** | モデルの大きさ、ライセンス、出力の扱いは、依頼文に書いてあるだけで、私は確かめていない。Logi は学習データにないので、意味の特定と逆翻訳の候補に限る。使うなら、先にライセンスを公式のページで確認する |
| サイトにモデルを載せない | 取り入れる | Q3 の A と同じ |

## 6. 守ること

- 仮の語は、画面でも記録でも「仮」と分かる印をつける。辞書の本体（`final.csv`）には、承認なしに書かない。
- LLM の出力は助言で、正しいと断定しない。意味の間違いは、ANTI の癖（`docs/proposals/021`）と同じ種類（英語の見出し語のずれ、既存語との重なり）が起きる前提で、`overlap_check.py` を通す。
- 公開サイトの入力は、個人情報を含み得る。記録は最小限にする（入力の語だけ。文は残さない）。
- 鍵・トークンは、リポジトリにもPR本文にも書かない。
