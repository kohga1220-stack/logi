# Antigravity の仕事の一覧（語の追加のほか）

M1ko の依頼（2026-10-24）: 「antiは作業量が多くてもいい。語句の追加の他に任せられる仕事があれば伝えて。長時間作業できる。語句の追加数を増やしてもよい」。
ここに、Antigravity に任せる仕事を、優先順に書きます。担当範囲（`docs/WORKFLOW.md` §2）は変わりません。どの仕事も、書いてよい場所だけに書き（`docs/review/`、`dictionary/sources/`、`dictionary/anti_additions.csv` など）、`tools/`・`tests/`・`web/translator.js`・`docs/grammar.md` は触りません。

## 仕事の流れ（1周）

```
仕事B（実文で足りない語を調べる）─┐
                                  ├→ 仕事A（語を足す。次のバッチの語は、仕事Bの結果から選ぶ）
仕事C（辞書の重複監査）───────────┘     ↑
                                         └ 仕事D（訳のおかしい文・併記の要望を Claude に渡す）
```

## 仕事A: 語を足す（バッチ）

- **語数**: 1バッチ **100語**まで（直前のバッチの【修正推奨】が 1割以下のとき。超えたら 50語に戻す。`docs/WORKFLOW.md` §2 手順5）。
- **語の選び方**: 仕事Bの「未登録語（多い順）」の上から選ぶ。よく使う語から足すためです。足りないときだけ、基本語彙から選ぶ。
- **事前確認**: `docs/WORKFLOW.md` §2 のとおり（`overlap_check.py --table` の出力をそのまま貼る。強い重なりの語は、例文で使い分けを書く。書けなければ外す）。
- **次のバッチを始める条件**: 前のバッチの Claude の確認（`word_review.csv` の note）と、直しのPRのマージが済んだら、M1ko の返事を待たずに始めてよい（M1ko が一任、2026-10-24。`docs/STATUS.md` に記録）。

## 仕事B: 実文で足りない語を調べる（最優先）

目的: 「どの語を足せば、実際の文が訳せるか」を、文から調べる。

1. 日本語の文と英語の文を、**自分で書く**（他の文章を写さない）。1ファイルに 100〜300 文、1行に1文。`#` で始まる行は注釈。
   テーマの例: 日常のあいさつ、家族、学校、買い物、料理、天気、体の調子、気持ち、旅行、仕事、スポーツ、趣味、ニュースの見出し風。
   置き場所: `dictionary/sources/sentences_<テーマ>.txt`。
2. `python tools/coverage_check.py dictionary/sources/sentences_<テーマ>.txt > docs/review/coverage_<テーマ>.md`
3. 出力の「未登録語（多い順）」が、足す語の優先順です。同じ語が何度も出るものを、仕事Aの候補にする。
4. 訳がおかしい文（語順がおかしい、助詞が落ちている、意味が違う）は、仕事Dへ。

終わりの目安: テーマごとに 1つのPR。`docs/review/coverage_*.md` と `dictionary/sources/sentences_*.txt` だけを変える。

## 仕事C: 辞書の重複監査（すでにある語の見直し）

目的: すでに辞書にある語どうしで、意味が重なる組を探す。

1. `pip install wn==0.0.23` を入れてから、`python tools/overlap_check.py --audit > docs/review/audit_pairs.md`（約 1,450 組）。
2. 表の「判断」の列を、1組ずつ書く。「同じ意味」か「別の意味」かと、**使い分ける場面を例文で1つ**。例文が書けない組は「同じ意味」とする。
3. 200組ごとに1つのPR（`docs/review/audit_judged_01.md`、`_02.md` …）。
4. 「同じ意味」とした組は、PR の本文に、別の表にまとめる: 残す語、消す語、残す語に併記する日本語・英語。
   **辞書の語は書き換えない**（`docs/WORKFLOW.md` §2 手順3）。消す・併記する作業は Claude が行う（M1ko が一任）。

## 仕事D: Claude への依頼を書く

仕事B・Cの途中で見つけた、次のことを `docs/STATUS.md` の「文法への依頼」に書く。1件につき1行。

- **訳のおかしい文**: 入力文、出力、何がおかしいか（例: 「助詞『で』が落ちている」）。Claude が翻訳機を直す。
- **併記の要望**: 「◯◯（既存語）に △△ を併記してほしい」。**書く前に、`dictionary/final.csv` で語・意味・英語を実際に引いて確かめる**（第29弾で、語を取り違えた依頼が 2件あった）。
- **文法が足りない**: 日本語・英語の言い方で、決まりがなくて訳せないもの。

## 仕事E（余裕があるとき）: 語彙の整理

- テーマ別の語彙一覧（`docs/review/vocab_by_theme.md`）。辞書にある語だけを、意味の日本語からテーマに分ける（食べ物、身体、天気、乗り物…）。語の追加はしない。分類が曖昧な語は「未分類」に入れる。
- 日本語の同じ読みで表記が違う語（頬/ほほ、眠る/寝る）の一覧。仕事Dの併記の要望の材料にする。

## 守ること

- 各PRは、1つの仕事だけにする。仕事A（語の追加）のPRに、仕事B・Cの成果物を混ぜない。
- 数字（語数、未登録語の数）は、ツールの出力をそのまま書く。実行していない数字を書かない。
- 実行できなかったこと、確かめていないことは、PR の本文に「未確認」と書く。
- 自分のブランチ（`anti/…`）だけを触る。語の追加だけのPRと、仕事B・Cの報告だけのPR（辞書の語を変えない）は、CI が成功したら自分でマージしてよい。
- 迷ったら、`docs/STATUS.md` の「文法への依頼」に書いて、Claude か M1ko に聞く。
